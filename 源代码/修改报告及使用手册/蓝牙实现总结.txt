一、实现目标
================================================================================

目标：彻底放弃WiFi模块，改用HC-05蓝牙模块进行数据传输至上位机页面。

变更对比：
- 原方案：ESP8266 WiFi + 机智云云平台 + WebSocket
- 新方案：HC-05蓝牙 + 透传模式 + Web Bluetooth API

四、硬件连接方案
================================================================================

ESP8266（移除）：
- VCC → 5V
- GND → GND
- TX → PA3 (USART2_RX)
- RX → PA2 (USART2_TX)
- EN → 3.3V
- RST → 复位引脚

HC-05（新增）：
- VCC → 5V
- GND → GND
- TX → PB11 (USART3_RX)
- RX → PB10 (USART3_TX)
- KEY → 悬空（透传模式）
- STATE → 不连接（可选）

================================================================================
五、引脚分配变更
================================================================================

新增引脚：
- PB10 → USART3_TX (推挽复用输出)
- PB11 → USART3_RX (浮空输入)

保留引脚（不变）：
- PA0 → ADC_CH0 (浊度传感器)
- PA1 → ADC_CH1 (pH传感器)
- PA2 → ADC_CH2 (TDS传感器)
- PA8 → DS18B20 (温度传感器)
- PB0 → 继电器控制
- PB6/PB7 → OLED (I2C)
- PC13 → 蜂鸣器
- PB12-PB15 → 按键

释放引脚：
- PA2 → 原USART2_TX (现已释放)
- PA3 → 原USART2_RX (现已释放)

================================================================================
六、软件架构变更
================================================================================

原架构：
STM32F103C8T6 → USART2(PA2/PA3) → ESP8266 → WiFi → 机智云云平台 → 上位机(WebSocket)

新架构：
STM32F103C8T6 → USART3(PB10/PB11) → HC-05 → 蓝牙 → 上位机(Web Bluetooth API)

================================================================================
七、数据传输协议
================================================================================

STM32 → HC-05 (USART3, 9600波特率)：
格式：JSON字符串，以\r\n结尾
示例：{"temperature":25.5,"ph":7.2,"turbidity":2.5}\r\n

字段说明：
- temperature: float, °C, 温度值，保留1位小数
- ph: float, pH, pH值，保留2位小数
- turbidity: float, NTU, 浊度值，保留1位小数

================================================================================
九、HC-05蓝牙模块配置
================================================================================

默认配置：
- 波特率：9600 bps (透传模式)
- 数据位：8位
- 停止位：1位
- 校验位：无
- 配对密码：1234 或 0000
- 工作模式：从机模式
- 工作电压：3.3V-5V DC
- 工作电流：约30-40mA
- 传输距离：约10米

AT指令配置（可选）：
- 修改名称：AT+NAME=STM32WaterMonitor
- 修改密码：AT+PSWD="1234"
- 修改波特率：AT+UART=9600,0,0
- 设置从机：AT+ROLE=0

注意：
- 发送AT指令需要KEY引脚置高电平
- AT指令波特率为38400 bps
- 透传模式波特率为9600 bps

十、使用步骤
================================================================================

步骤1：硬件连接
1. 断开ESP8266模块连接
2. 连接HC-05到STM32：
   - HC-05 VCC → 5V
   - HC-05 GND → GND
   - HC-05 TX → PB11 (USART3_RX)
   - HC-05 RX → PB10 (USART3_TX)
   - HC-05 KEY → 悬空（透传模式）

步骤2：STM32编程
1. 打开Keil uVision项目
2. 添加 SYSTEM/USART/usart3.c 到项目
3. 编译项目
4. 使用ST-Link或J-Link连接STM32
5. 烧录程序到STM32F103C8T6

步骤3：上位机连接
1. 使用Chrome或Edge浏览器
2. 打开 index_bluetooth.html 文件
3. 点击"连接蓝牙"按钮
4. 选择HC-05设备进行配对
5. 输入配对密码（1234或0000）
6. 连接成功后开始接收数据

步骤4：数据验证
1. 观察上位机页面是否显示传感器数据
2. 检查连接状态指示器是否变绿
3. 检查实时趋势图是否正常绘制
4. 检查系统日志是否正常显示

十二、故障排查
================================================================================

问题1：无法连接蓝牙设备
可能原因：
- 浏览器不支持Web Bluetooth API
- 未使用HTTPS或localhost
- HC-05未上电或工作异常

解决方法：
- 使用Chrome 56+或Edge 79+浏览器
- 确保使用HTTPS或localhost
- 检查HC-05电源和LED状态
- 重置HC-05（断电重启）

问题2：数据不更新
可能原因：
- STM32未发送数据
- 蓝牙数据格式错误
- 波特率不匹配

解决方法：
- 检查STM32串口输出，确认USART3初始化成功
- 检查SendBluetoothData函数是否被调用
- 确认STM32和HC-05波特率一致（9600）
- 检查数据格式是否为正确的JSON格式

问题3：连接频繁断开
可能原因：
- WiFi信号弱或干扰
- HC-05电源不稳定
- 蓝牙超出传输距离

解决方法：
- 确保HC-05使用稳定5V电源
- 缩短设备间距离
- 避免蓝牙信号干扰源

问题4：数据乱码
可能原因：
- 波特率不匹配
- 数据格式错误
- 通信干扰

解决方法：
- 确认STM32和HC-05波特率一致（9600）
- 检查TX/RX交叉连接是否正确
- 检查HC-05的TX接STM32的RX，RX接STM32的TX

================================================================================
十三、注意事项
================================================================================

1. 波特率匹配：STM32的USART3和HC-05的波特率必须一致（9600）

2. TX/RX交叉连接：
   - HC-05的TX接STM32的RX (PB11)
   - HC-05的RX接STM32的TX (PB10)

3. 电源稳定：
   - HC-05工作电流较大（约30-40mA）
   - 建议使用独立5V供电

4. 浏览器支持：
   - Web Bluetooth API只支持Chrome、Edge、Opera
   - 不支持Firefox和Safari

5. HTTPS要求：
   - 生产环境必须使用HTTPS
   - 开发环境可使用localhost

6. 用户手势：
   - 蓝牙连接必须由用户点击按钮触发
   - 不能自动连接

7. 距离限制：
   - 蓝牙有效传输距离约10米
   - 注意使用环境

8. 数据频率：
   - 控制数据发送频率，避免蓝牙传输过载
   - 建议每秒1-2次数据更新
